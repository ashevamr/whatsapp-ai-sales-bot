# Как собрать нового бота на этом фундаменте

Здесь описано, что брать как есть, а что заменить под новый бизнес.

## Переиспользуемое ядро — брать без изменений

| Модуль | Что даёт |
|---|---|
| `scripts/supervise_bot.js`, `scripts/start_bot.ps1` | Один процесс, перезапуск, watchdog, автозапуск в Windows |
| `bot_reliability.js` | Таймауты, журнал входящих (защита от дублей), повторная обработка после обрыва |
| `automation_safety.js` | Можно ли сейчас отвечать (пауза, READY, сообщение из текущей сессии) |
| `inbound_message_guard.js` | Отсев своих сообщений, групп, статусов |
| `automated_outbound_guard.js` | Распознавание эха собственных отправок |
| `voice_safety.js` | Распознавание голосовых, пауза при неразборчивой речи |
| `conversation_safety.js` | Анти-повторы, фильтр пачек, защита адреса и оформления, намерение купить |
| `attachment_safety.js` | Шаблон правила «файл только выбранной модели» |
| `ai_workflow.js` | `formatSalesReply`, `splitIntoBubbles`, `protectUrls`, `executeWithFallback`, нормализация истории, порядок «код → LLM → запасной ответ» |
| `server.js` | Очередь по чатам, дедупликация, отложенные входящие, переподключение, READY recovery, проверка соединения, сохранение, «печатает» и пузыри, Smart Takeover, режимы автоматизации, ежедневный отчёт, API и панель |
| `public/index.html`, `public/app.js` | Панель оператора |

## Бизнес-часть — заменить

1. **`commercial_facts.js`** — товары, цены, рассрочка, акции, города со складами, время отсечки доставки. Это первое, что пишется для нового бизнеса.
2. **Инструкция продавца** в `ai_workflow.js` (`CONCISE_SALES_INSTRUCTION`): имя и роль, воронка, особенности региона.
3. **Меню и шаблоны** в `ai_workflow.js`: первое сообщение, ответы на возражения, сравнение типов товаров.
4. **Пакеты материалов** в `server.js`:
   - пути к файлам в папке контента и подписи (`send…Bundle`, блоки с `sendPic`);
   - ключевые слова, по которым понятно, о какой модели речь (`detectCatalogModelsInText` в `commercial_facts.js`).
5. **Контекст рекламы** (`ad_context.js`): какие слова в объявлении указывают на какую модель.
6. **Фразы-триггеры**: «подумаю», «оформляем», подтверждение продажи, отмена (в `server.js`).
7. **Промпт для фото** (Vision): какие категории фото важны для этого бизнеса.
8. **Повторные касания** (`follow_up_suggestions.js`, `alkaline_silence_followup.js`): тексты и условия.
9. **`.env`**:
   - `GEMINI_API_KEY`;
   - номер супервизора — `SUPERVISOR_PHONE`;
   - номер владельца — `TAKEOVER_OWNER_PHONE`;
   - название группы со сделками — `SUCCESS_CASES_GROUP_NAME`.
10. **Папка контента** (`Vodel content/<NN_Model>/`): `info.txt` и медиа модели.

## Порядок работы

1. Скопировать репозиторий и удалить бизнес-тесты, относящиеся к старым моделям.
2. Заполнить `commercial_facts.js` и написать для него тест (как `test_commercial_facts.js`).
3. Переписать инструкцию продавца и меню. Оставить правила формата: коротко, один вопрос, без повторного приветствия, без имён файлов.
4. Подключить материалы моделей с правилом «только выбранная модель, один раз за чат».
5. Запустить `npm run test:safety`. Тесты надёжности и безопасности ядра должны пройти без изменений.
6. Запустить бота в режиме `paused`, проверить панель и включить `new_leads_only`.

## Чему научил первый бот

- **Всё, что связано с деньгами и обещаниями, — в коде, не в промпте.** Модель «помнит» цену из старой базы знаний и уверенно её называет.
- **Любое правило без теста рано или поздно ломается при следующей правке.**
- **Перед правкой живого бота — резервная копия или git.** Перезапуск — осознанно, а не автоматически (`npm start`, не `nodemon`).
- **`server.js` вырос до одного большого обработчика.** Для следующего бота стоит сразу разделить его на конвейер ядра и «обработчики намерений» бизнеса.
