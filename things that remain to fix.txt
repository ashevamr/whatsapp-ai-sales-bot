BUGS FOUND & FIXED
================================================================================

BUG 1: DUPLICATE `const isExplicitKaspiOrProof` DECLARATION (CRITICAL)
  FILE: server.js
  LINES: 330 and 386 (old)
  PROBLEM: The variable `isExplicitKaspiOrProof` was declared with `const` on
    line 330 (used by `shouldSendAlbum` guard) AND again on line 386 (used by
    the Kaspi proof section). In non-strict mode, the second `const` in the
    same function scope would shadow the first, creating two independent
    variables. This meant the `!isExplicitKaspiOrProof` guard on
    `shouldSendAlbum` (line 348) referenced the FIRST declaration, while the
    Kaspi proof conditional (line 389) used the SECOND — making behavior
    unpredictable and preventing the album-blocking guard from working reliably.
  FIX: Removed the duplicate declaration on line 386. Now there is a single
    `isExplicitKaspiOrProof` (line 330) used consistently by both the album
    guard AND the Kaspi proof section.
  STATUS: ✅ FIXED

BUG 2: `aiSaysSendingPhotos` TRIGGERED BY KASPI PROOF CONTEXT (CRITICAL)
  FILE: server.js
  LINES: 339-342
  PROBLEM: When customer asks "Покажи мне где он стоит 420 тысяч" and the AI
    responds "Конечно, сейчас отправлю вам скриншот с маркетплейса", the phrase
    "сейчас отправлю" caused `aiSaysSendingPhotos = true`. Combined with the
    duplicate variable bug above, this bypassed the `isExplicitKaspiOrProof`
    guard and dumped the entire FOURA product album alongside the Kaspi proof
    screenshot.
  FIX: Added `aiTalksAboutKaspiProof` guard that detects when the AI reply
    contains "скриншот", "маркетплейс", or "доказательств". When the AI is
    talking about sending a Kaspi proof screenshot (not product photos),
    `aiSaysSendingPhotos` is now forced to `false`.
  STATUS: ✅ FIXED

BUG 3: INCOMPLETE STATE RESET ON CHAT CLEAR (MINOR)
  FILE: server.js
  LINE: 570-574
  PROBLEM: The `/api/chats/:id/clear` endpoint reset `albumSent` but did NOT
    reset `kaspiSent` or `membraneSent`. This meant clearing a chat from the
    dashboard did not fully reset the media dispatch state — the Kaspi proof
    and membrane diagram would never re-send even in a fresh conversation.
  FIX: Added `chats[chatId].kaspiSent = false` and
    `chats[chatId].membraneSent = false` to the clear endpoint.
  STATUS: ✅ FIXED
